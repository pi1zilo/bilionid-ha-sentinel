# BilioniD HA Sentinel — Отчет по безопасности и модель угроз

## 1. Концепция безопасности

Проект **BilioniD HA Sentinel** спроектирован в соответствии с принципами **Least Privilege (Минимальные привилегии)**, **Defense in Depth (Эшелонированная оборона)** и **Zero-Trust Network Isolation**.

Бот предназначен исключительно для приватного использования владельцем инфраструктуры. Любые публичные или неконтролируемые векторы воздействия исключены на уровне архитектуры.

---

## 2. Модель угроз и меры защиты

| Вектор угрозы | Уровень риска | Архитектурная мера противодействия |
|---|:---:|---|
| **Попытка доступа постороннего через Telegram** | Высокий | Strict Whitelist Middleware (`OwnerAuthMiddleware`). Проверяется каждый запрос к боту. Если `user.id != TELEGRAM_ADMIN_USER_ID`, бот отклоняет запрос, логирует попытку доступа и блокирует дальнейшую обработку. |
| **DoS / Спам командами в Telegram** | Средний | Sliding Window Rate Limiter (`RateLimitMiddleware`). Ограничивает частоту запросов (по умолчанию 30 запросов в минуту). При превышении бот выдает предупреждение без нагрузки на бекенд. |
| **Утечка Bot Token или HA Secret в Git** | Критический | Строгий `.gitignore`, исключающий `.env`, `*.db`, `logs/`. В репозиторий помещается только `.env.example` с фиктивными плейсхолдерами. Права на боевой `.env` принудительно устанавливаются в `chmod 600`. |
| **Утечка секретов в логах приложения** | Высокий | Фильтр логирования `SensitiveDataFilter` и JSON-форматтер. Все ключи и значения с подстроками `token`, `secret`, `key`, `password` автоматически маскируются (например, `123***YZ`). Метод `Settings.masked_dict()` скрывает секреты при диагностике. |
| **Несанкционированный доступ к HA-endpoint** | Высокий | Привязка к приватной сети Tailscale (`100.x.x.x`). Защита служебных endpoints заголовком `X-HA-Secret` (32-байтный hex-ключ). Запросы без ключа или с неверным ключом отклоняются с кодом `401 Unauthorized`. |
| **Эскалация привилегий через Docker** | Высокий | Контейнер запускается под непривилегированным пользователем `appuser` (UID 1000). Включена опция `security_opt: [no-new-privileges:true]`. Флаг `privileged` запрещен. Сокет Docker монтируется строго в режиме **read-only** (`/var/run/docker.sock:ro`). |
| **Несанкционированное изменение инфраструктуры** | Критический | Принцип **Read-Only по умолчанию**. В текущей версии бот не выполняет системные команды, не перезапускает сервисы и не изменяет файлы хоста. Вся функциональность ограничена телеметрией. |
| **Конфликт со сторонними сервисами (Beszel / Uptime Kuma)** | Средний | Бот не меняет конфигурацию чужих Docker Compose проектов, не сбрасывает чужие вебхуки и не перезапускает чужие контейнеры. Порты проверены установщиком (порт `29010` свободен на обоих VPS). |

## 3. Проверка авторизации (Аудит кода)

В `app/bot/middlewares/auth.py`:
```python
if user.id != self.admin_user_id:
    logger.warning("UNAUTHORIZED ACCESS ATTEMPT: user_id=%s, username=@%s", user.id, user.username)
    # Сообщение об отказе и прекращение обработки события
    return
```
Любое событие от пользователя с иным ID прерывается до вызова какого-либо роутера или обработчика.

## 4. Защита HA Endpoint (Межсерверное взаимодействие)

Служебный порт `29010` не должен публиковаться в публичный интернет через порты роутера/провайдера. Он предназначен для взаимодействия строго внутри защищенной виртуальной сети Tailscale (CGNAT адресация `100.x.x.x`).

Все входящие вызовы на `/ha/status`, `/ha/heartbeat`, `/ha/yield`, `/ha/containers`, `/ha/force_role` валидируют pre-shared секретный ключ:
```python
def _verify_secret(self, request: web.Request) -> bool:
    secret = request.headers.get("X-HA-Secret")
    if not secret:
        auth_header = request.headers.get("Authorization", "")
        if auth_header.startswith("Bearer "):
            secret = auth_header[7:]
    return secret == self.settings.HA_SECRET_KEY
```

## 5. Аудит зависимостей и Dockerfile

- Базовый образ: официальный `python:3.11-slim` с минимальной поверхностью атаки.
- Регулярная очистка пакетного кэша `apt-get clean && rm -rf /var/lib/apt/lists/*`.
- Все зависимости зафиксированы в `requirements.txt` с контролем мажорных версий.
- Изоляция хранилища: локальная база данных SQLite находится в отдельной директории `./data`, монтируемой в `/app/data` с правами `chmod 700`.
